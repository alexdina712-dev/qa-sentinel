## Try it

Click **Explore a private demo**. Create a work item, edit its status, try search/filters, and inspect Activity. Each visitor gets separate fictional data. Public data may reset when free hosting restarts; use fictional details only. The first request may take time while the free server wakes.

For the installed Desktop copy, double-click **Start QA Sentinel.cmd**. It opens http://127.0.0.1:5178 after starting the local servers. Use **Stop QA Sentinel.cmd** when finished. Local data survives restart. Internet access is needed for the first dependency installation.

## What to show an employer

1. README and the live app.
2. TEST_PLAN.md and TEST_CASES.md: what is tested and why.
3. BUG_REPORT_EXAMPLES.md and the mutation evidence: four deliberately introduced bugs caught by tests.
4. GitHub Actions: actual automated runs and downloadable reports.
5. PORTFOLIO_CASE_STUDY.md: architecture, decisions, limits and AI assistance.

This is a project you can study and explain. Before interviewing, practice running one test, reproducing one deliberate defect, inspecting a trace, and explaining the fix in your own words.

Docker support is provided but was not executed locally because Docker is unavailable. Mobile tests are Chromium emulation, not a claim of real iPhone/Safari testing. Full details and dated results are in the README and docs/evidence.
